1. EXECUTIVE OVERVIEW & CORE ARCHITECTURAL PRINCIPLE
--------------------------------------------------------------------------------
AgentGuard AI SOC is an end-to-end autonomous security operations center built for
healthcare clinics and small-to-medium organizations. It ingests multi-source
telemetry (authentication logs, web traffic, database queries, filesystem activity,
email drops, and DNS traffic), correlates them into actionable incidents, explains
threats in plain language using AI, and routes remediation actions through a
mathematically deterministic policy gateway.

THE CARDINAL SECURITY PRINCIPLE:
  "The AI may recommend; only the deterministic policy gateway may authorize.
   Event text, email text, usernames, URLs, and any log fields are untrusted
   DATA, never instructions, and are never used to construct titles, reasons,
   targets, or prompts without escaping, bounding, and scope validation."

SIMULATION & SAFETY GUARANTEES:
  1. 100% Localhost Sandbox: Attack simulators refuse non-localhost targets.
  2. Safe Sandbox File Burst: Modifies only test files inside C:/demo_sandbox/
     with strict path traversal checks. Never performs real encryption.
  3. No Shell Execution: Untrusted log fields are never passed to eval or system
     shells.
  4. Zero Secret Leakage: Authentication tokens and HMAC secrets are sanitized
     before audit persistence and SSE broadcasting.

4. CORE FUNCTIONAL MODULES & HOW THEY WORK
--------------------------------------------------------------------------------

A. TELEMETRY INGESTION & NOISE REDUCTION FUNNEL
  - Incoming raw events are ingested via POST /api/ingest/events.
  - The pipeline filters normal background noise (e.g. single login failures,
    routine file edits, scheduled backup tasks with process backup_agent.exe).
  - Multi-signal correlated threats rise through the funnel:
      Raw Events -> Filtered Noise -> Candidates -> Actionable Incidents
  - Real-time conversion counts are exposed at GET /api/funnel.

B. DETERMINISTIC DETECTION ENGINE (detection/pipeline.py)
  - Account Takeover:
      R1: >= 5 auth failures for same user and src_ip within 2 minutes.
      R2: Auth success from same user and src_ip within 5 minutes of R1.
      R3: Auth success from an IP not in user's known_ips baseline.
      R4: Privilege change within 30 minutes of anomalous login (-> CRITICAL).
  - File Burst & Ransomware:
      F1: >= 100 file modifications in 60s with non-.bak extension.
      F2: Backup tampering (e.g. vssadmin delete shadows) within 5m (-> CRITICAL).
      F3: Ransom note file creation (README_RESTORE, etc.) cited in evidence.
      Allowlist: Scheduled backup tasks by backup_agent.exe generate 0 incidents.
  - Web Attack (W1/W2):
      W1: Matches SQL injection and directory traversal regexes on URL-decoded
          parameters. Records only rule ID and escaped snippets. Never leaks
          attacker payload text into incident titles.
      W2: Repeated W1 probes (>= 3 in 5 min) or >= 20 req/min to /login or /admin.
  - Data Exfiltration (D1/D2):
      D1: >= 50 data accesses within 2 minutes or bulk export above size limit.
      D2: Admin login followed by D1 within 30 minutes (-> CRITICAL multi_stage).
  - Correlation Rules:
      Correlates events sharing the same user_id or host_id within 30 minutes,
      tagging the incident with LINK_SAME_USER_30M or LINK_SAME_HOST_30M. A
      preceding phishing check event upgrades category to multi_stage.

C. VERIFIED POLICY GATEWAY (backend/policy/)
  - Evaluates remediation proposals strictly without network or LLM dependencies:
      P1: Incident Exists & Open: Closed incidents cannot be actioned.
      P2: Valid Action Type: lock_account, isolate_host, revoke_session.
      P3: Category Allowlists:
          * account_takeover         -> {lock_account, revoke_session}
          * ransomware_like_activity -> {isolate_host}
          * web_attack               -> {isolate_host, revoke_session}
          * data_exfiltration_suspected -> {lock_account, revoke_session}
          * multi_stage              -> {lock_account, isolate_host, revoke_session}
      P4: Deterministic Target Scoping:
          * lock_account / revoke_session MUST match an entry in affected_users.
          * isolate_host MUST match an entry in affected_hosts.
          * Any attempt to action an unlisted target (e.g. 'ceo') is deterministically
            BLOCKED with reason code TARGET_OUT_OF_SCOPE.
      P5: Role Check: Staff (analysts) may preview; Approver (leads) required
          to approve.
      P6: Human-In-The-Loop: In-scope actions resolve to REVIEW (APPROVAL_REQUIRED).

D. SINGLE-USE HMAC-SHA256 TOKEN GATEWAY
  - Upon lead approver authorization, the gateway mints a signed execution token:
      base64url(claims) + "." + base64url(HMAC-SHA256(secret, claims))
  - Claims encode: iss, aud, token_id, nonce (32 hex), incident_id, action_type,
    target_id, iat, and exp (60s TTL).
  - Enforcement Tool Verification:
      Checks token signature, scope matching, and active expiration window.
      Executes an atomic SQL INSERT on the nonce into a unique-constrained table.
      Replay attempts are instantly rejected with TOKEN_REPLAYED.

E. AI EXPLANATION ENGINE (backend/ai/adapter.py)
  - Driven by Gemini 2.5 Flash with strict Guarded Mode prompt separation:
      All event attributes are JSON-encoded, length-capped at 300 characters,
      and explicitly framed as UNTRUSTED DATA.
  - Output Validation: Parses structured JSON; strips any hallucinated event IDs
    not present in evidence; drops any recommended action targets outside the
    affected scope.
  - Resilient Fallback: If the LLM times out or is offline, an immediate fallback
    explanation is returned. The system NEVER raises HTTP 500 on AI errors.

F. REAL-TIME SERVER-SENT EVENTS (SSE) & LIVE UPDATES
  - GET /api/stream publishes real-time UI events:
      incident_created, incident_updated, response_updated, audit_appended
  - Safe payload design: SSE messages transmit strictly IDs and types, preventing
    XSS or injection payload leakage to client sockets.
  - Frontend useLiveUpdates hook connects via EventSource with automatic fallback
    to 5-second polling and visual LIVE / POLLING status pill.

G. TAMPER-EVIDENT CRYPTOGRAPHIC AUDIT LEDGER (backend/audit/)
  - Every action proposal, policy decision, approval, token issuance, and execution
    is appended to an SHA-256 hash chain:
      event_hash = sha256(previous_hash + canonical_json(payload))
  - Genesis block begins with 64 zeros.
  - Verification endpoint GET /api/audit/verify recomputes every block hash from
    genesis and pinpoints the exact sequence number if any row was tampered with.

H. CLINIC SITE ADAPTER & LOG COLLECTOR (Phase 3)
  - testbed/stub_site/main.py: Real FastAPI clinic site (port 8002) emitting:
      auth.log: Login failures and successes.
      access.log: HTTP requests with query strings and paths.
      data.log: Patient medical record query tracking.
      Admin API: /admin/users/{user}/lock and /admin/hosts/{host}/isolate.
  - collector/collector.py: Tails log files with persistent byte offsets and
    POSTs mapped events to the gateway.
  - Protected mock tool supports Portal Mode, proxying authorized executions
    directly to the clinic site Admin API.
